# Divine Knowledge Authority

Status: OWNER-APPROVED STANDING AUTHORITY

Owner authorization date: 2026-08-26

## Purpose

`docs/divine-knowledge/**` is the project assistant's durable TornScriptures continuity and retrieval system.

The owner explicitly authorizes the project assistant, across future TornScriptures threads, to create, read, write, edit, reorganize, rename, consolidate, supersede, archive, and delete content inside this subtree when the assistant judges that doing so improves project memory, correctness, retrieval, or organization.

The owner does not need to approve ordinary knowledge-tree maintenance entry by entry.

## Standing maintenance authority after bootstrap merge

After the bootstrap PR establishing this authority is merged, the owner adopts a narrow documentation-maintenance exception: the project assistant may make documentation-only direct commits to `main` for paths strictly beneath `docs/divine-knowledge/**` when maintaining project memory.

This exception exists to preserve useful decisions and state without opening a PR for every small memory update.

It does not extend to any file outside the subtree.

## Explicitly outside this authority

Standing Divine Knowledge authority does not authorize the assistant to:

- merge pull requests;
- enable auto-merge;
- delete branches;
- edit product/runtime userscripts under this exception;
- alter tests, workflows, repository configuration, or normal docs outside the subtree;
- change gameplay behavior;
- weaken safety, accounting, or confirmation boundaries;
- mutate Black Ledger/user data;
- spend money;
- expose credentials or private data;
- reinterpret a memory note as implementation or release authorization.

Normal TornScriptures governance remains authoritative for those actions.

## Transparency and reasoning boundary

The subtree may use compact machine-oriented notation, but `SCHEMA.md` must keep that notation self-decoding. The subtree stores conclusions, rationale summaries, provenance, plans, relationships, and project state. It must not attempt to preserve hidden chain-of-thought or private internal reasoning transcripts.

## Security boundary

Do not store API keys, cookies, session tokens, passwords, authorization headers, private inventory exports, unnecessary personal identifiers, sensitive personal information, or raw private conversations merely because they occurred.

## Deletion and recovery

The owner explicitly permits deletion inside this subtree. The assistant should normally prefer supersession/archive for substantive history and may delete duplicated, corrupt, misleading, mechanically obsolete, or retrieval-hostile material. Git history remains the recovery layer.

## Owner control

The owner may amend, narrow, suspend, or revoke this standing authority at any time. A later explicit owner instruction supersedes this document.
